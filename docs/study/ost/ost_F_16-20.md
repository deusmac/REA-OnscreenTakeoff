# OST notes F: categories 16 to 20 (import/export, sharing, comments, masters, options, databases)

### 16.01 Import/export overview (id 825)
- OST-16-001 Exportable: Projects list (as report via Print Preview); Summary tab and Estimate (Worksheet) tab to CSV, report, or clipboard copy; bid without images as takeoff file (.ost); bid package (.osp) with optional images.
- OST-16-002 Importable: bids from .ost or .osp; iSqFt assemblies (to seed Condition Styles); employees from a CSV template; Master tables from another database via synchronization.
- OST-16-003 A file can only be imported into the same or a newer program version than created it.
- OST-16-004 Importing an .osp into a database already holding that bid overwrites it after a prompt; safe workaround is import into a fresh database then copy/paste the bid across.
- OST-16-005 Image paths: collate all plan files in one folder before exporting a package, else links break on the recipient side.
- UNKNOWN: exact internal format of .ost/.osp (not described; treat as opaque, our own format needed).

### 16.02 Print preview and export of tab reports (id 826)
- OST-16-006 Projects, Summary, Estimate tabs each have a Print Preview button producing a report; report honors the tab's active sort, filter and group settings.
- OST-16-007 Export dialog: pick Format (PDF and Excel most common; Word also tested) and Destination (disk file recommended; or send direct to an installed app).
- OST-16-008 The Takeoff (image) tab is not "exported"; its plans and takeoff are printed, or the whole bid is exported as a file.
- UNKNOWN: report column layouts and page templates.

### 16.03 Copying rows from Summary/Estimate (id 827)
- OST-16-009 Right-click a row > Copy; multi-select via Ctrl-click, Shift-click range, or rubber-band drag from bottom-right toward upper-left; selected rows turn blue; paste into any spreadsheet.
- OST-16-010 Works the same on the Estimate tab.
- UNKNOWN: whether copied text is tab-delimited and whether headers/group rows are included.

### 16.04 Export Summary/Estimate to CSV (id 828)
- OST-16-011 File > Export (to takeoff file entry) from Summary or Estimate tab; the only format offered is comma-delimited CSV; user names the file and saves.
- UNKNOWN: column order and number formatting in the CSV.

### 16.05 Exporting bids overview (id 829)
- OST-16-012 .osp bid package: may include image files and comments. .ost takeoff file: page names, takeoff, areas, conditions only, no images. Both carry every condition and all takeoff.
- OST-16-013 Creating an .osp requires a licensed (not viewer-only) user.
- OST-16-014 Pre-export advice: put images in one folder, relink via Cover Sheet, clear the Image Folder path so each page shows a full path, keep paths under 128 characters, convert PDFs to TIF so each page maps to a unique file, send only needed pages.
- OST-16-015 Two routes: Send function (builds .osp) or File > Export to .osp/.ost. .ost can feed some estimating programs.

### 16.05.01 OSP vs OST differences (id 830)
- OST-16-016 OSP: can include images; was sendable via Project Express; overwrites same bid on import (or creates new, see 16.06.01); from a secured database it creates its own new secured database on import.
- OST-16-017 OST: always creates a new bid on import, never updates one; no images; can create/update a QuickBid project; carries no security info.
- OST-16-018 Use OSP when recipient lacks the plans; OST when recipient already has plans and only needs updated quantities, or when sending to a QuickBid user for pricing.
- OST-16-019 Data flow: the .ost file is the takeoff-to-bidding handoff to QuickBid (creates/updates a QB project).

### 16.05.02 Sending a bid package (id 831)
- OST-16-020 Send packages Base Bid, Alternates and Change Orders. Channels: email (MAPI client), file, Project Express (retired after April 2026, replaced by cloud sharing).
- OST-16-021 Create Bid Package dialog: Send Images yes/no; if yes, Range = All Pages, Pages with Takeoff, or Custom Select Images (checkbox list of pages, uncheck to omit). Pages with Takeoff always includes the active page even if empty.
- OST-16-022 File name default pattern: bid number, bid name, date as mmddyyyy, extension .osp; default folder is the Package Folder option.
- OST-16-023 Email size limit about 10 MB commonly blocks packages with images.
- OST-16-024 Importing a partial package over an existing bid deletes pages not included (after confirmation).
- OST-16-025 Secured source database: recipient gets a new database flagged login-required with no employees; needs an admin-level employee added. To avoid, copy bid to an unsecured database first.

### 16.05.03 Exporting to a bid package manually (id 832)
- OST-16-026 Package carries the creating version tag; import denied if installed version is older (rule from version 3.98.07).
- OST-16-027 Entry: File > Export or right-click bid on Projects tab > Export > To Bid Package. Range options add one more: Pages with Takeoff and Comments.
- OST-16-028 If bid is passed back and forth between estimators always use All Pages; otherwise omitted pages are removed from the overwritten bid irretrievably.
- OST-16-029 Image file name plus full path must be under 128 characters.
- OST-16-030 Default export location is the OST documents folder; configurable in Folders options.
- OST-16-031 Large PDFs (2 MB or more per page) make packages exceed 10 MB fast.

### 16.05.04 Exporting a takeoff file (id 833)
- OST-16-032 File > Export (or right-click project) > To Takeoff File; default file name is bid name with an incrementing number in parentheses.
- OST-16-033 Known issue (v4.0+): an .ost only includes pages that have takeoff. Workaround: place one dummy Count object on each page to keep.
- OST-16-034 Takeoff files are small enough for email.

### 16.05.05 Exporting condition results to CSV (id 834)
- OST-16-035 From Summary tab: File > Export > takeoff file, only CSV option. Output uses same group-by as the tab, no column header row.
- UNKNOWN: whether subtotals are written.

### 16.06 Importing overview (id 835)
- OST-16-036 Importable: .osp, .ost, .osx, iSqFt assemblies. Same-version import recommended.
- OST-16-037 .osx is a planroom-sourced project file allowing plan download from the Conditions window.
- OST-16-038 OST from a secured database carries no security and imports anywhere.

### 16.06.01 Importing bid packages (id 836)
- OST-16-039 Entry points: File > Import > Bid Package File, double-click an .osp attachment, or double-click an item in the Project Express list.
- OST-16-040 From version 3.98.07.57: if the bid already exists, prompt offers Create New Bid (default) or Overwrite Bid. Create New assigns a brand new internal ID, disconnecting it from the origin bid.
- OST-16-041 Older versions always overwrite.
- OST-16-042 For Digital Production Control bids, overwrite is mandatory; new-bid import permanently breaks the DPC link.
- OST-16-043 If no database open, importing by double-click creates a new Access database named after the project.
- OST-16-044 Missing master records (layers, condition types, etc.) are auto-created during import; import into a clean database to avoid polluting masters.
- OST-16-045 Bid identity concept: a bid has a persistent origin ID used to match incoming packages (needed for our design).

### 16.06.02 Importing takeoff files (id 837)
- OST-16-046 File > Import > Takeoff file (.ost, .osx); creates a new Project each time, then opens the Cover Sheet for edits, then the Takeoff tab. Existing copies never overwritten.
- OST-16-047 File extension association can be hijacked by other apps (Outlook); fix with Open With.

### 17.01 Project Express overview (id 839)
- OST-17-001 Legacy file-sharing service (versions up to 4.0.0.405), retired and replaced by cloud sync on 21 July 2026. Needed active maintenance, internet, Windows 11, valid licence; 60-day grace after lapse.
- OST-17-002 Workflow: Send button builds a bid package, then message box with sender info; recipient double-clicks file in Inbox.
- OST-17-003 Contacts can be stored in the database (employee list with email) for recipient picking.
- OST-17-004 Receiving an update overwrites the project (later versions prompt, see 16.06.01).

### 17.02 Project Express tab (id 840)
- OST-17-005 Tab has Inbox and Outbox views, remembers last-viewed box until app restart. Context menu: Download, toggle display of already-downloaded files. Double-click also downloads and imports into current database.
- OST-17-006 Tab shows a notification marker when undownloaded files exist.

### 17.03 Registering (id 841)
- OST-17-007 Account requires email, password (min 8 characters, at least one upper and one lower case), all fields mandatory; email confirmed by pasting a registration code.
- OST-17-008 Unlicensed viewer or lapsed users get a time-limited trial.
- (Account/support specifics otherwise skipped as licensing content.)

### 17.04 Signing in (id 842)
- OST-17-009 Sign in with email as username and password via Refresh Info; maintenance expiry displayed. Sign out by clearing both fields and saving.
- OST-17-010 Files are never emailed; only a notification is.

### 17.05 Sending (id 843)
- OST-17-011 Send form: To (semicolon-separated emails, can pick from employee list), Subject (editable; DPC change files should include estimated or earned hours), file name fixed.
- OST-17-012 Uploaded files expire after 14 days.
- OST-17-013 DPC change files must be imported in the order sent.
- OST-17-014 Password prompt with a remember-password option.

### 17.06 Receiving (id 846)
- OST-17-015 Notification on tab switch, Inbox refresh, or app start. Double-click downloads and auto-imports to active database; afterward returns to Projects tab with that bid selected.
- OST-17-016 Re-importing the same bid triggers the overwrite-or-new prompt (same rules as OST-16-040/042).

### 17.07 Refreshing (id 847)
- OST-17-017 Inbox and Outbox refresh separately; tab does not auto-refresh while open but refreshes on selecting the tab. Each refresh rechecks subscription.

### 17.08 Comments overview (id 280)
- OST-17-018 Comments are threaded (comment plus replies), stored per Page, permanent unless the Page is deleted (with confirmation). Require current maintenance.
- OST-17-019 Comments are scoped per bid: Base Bid comments not visible in Alternates or Change Orders. Copy/duplicate of a bid copies comments.
- OST-17-020 Comments are not takeoff or annotation, so page colour-coding does not flag them. Workaround: dummy Count condition per page, then group Summary by page.
- OST-17-021 Sharing: shared SQL database (just read the Comments list) or via OSP packages. Access databases must never be shared. Only the first user opening a bid in shared SQL can edit it; lock released when that user closes it.
- OST-17-022 Comments layer is a permanent system layer (see 18.06).

### 17.08.01 Adding a comment (id 338)
- OST-17-023 Add via right-click in image window > New Comment, or New Comment button in Comments tab, then click plan to place the icon.
- OST-17-024 Fields: author name (max 50 chars; auto-filled when logins are on), icon colour, comment text (max 250 chars). Avoid single quote, double quote and dash in these fields (break package import/export).

### 17.08.02 Replying (id 244)
- OST-17-025 Open by double-click on header in list or icon on plan, or select header and use toolbar reply button. Reply dialog has name and text; changing colour on reply recolours the plan icon and list icon (used for status coding).

### 17.08.03 Sending and receiving comments (id 460)
- OST-17-026 .ost files do not include comments; only .osp (optionally).
- OST-17-027 Recommended collaboration pattern: each user keeps a working copy for takeoff and a separate "comments copy" bid; incoming packages are imported as New Bid, then takeoff is copy/pasted into the working copy. Overwrite is discouraged.
- OST-17-028 Range choice "All Pages" or "Pages with Takeoff and Comments" when sending.
- OST-17-029 First import of a bid gives no prompt.

### 17.08.04 Comments list (id 328)
- OST-17-030 Comments tab in Conditions window lists comments and replies for current page; items collapsible; double-click header opens; buttons at bottom for new comment and reply.

### 17.09 Project CloudSync (id 2774)
- OST-17-031 Replaces Project Express from version 4.0.0.881 (21 July 2026); needs the subscription build that licenses by email and password.
- OST-17-032 A pseudo-database named for the organization appears on Projects tab; "Send to Cloud" button on main toolbar and context menu.
- OST-17-033 Upload makes an OSP of the project with all pages and uploads it; visible instantly to all org users, no notification.
- OST-17-034 Download: right-click > Send to Local, confirm, choose target among open databases; extracted into it. Location column on Projects tab shows where a project lives.
- OST-17-035 Delete from Cloud removes only the cloud copy; local imports unaffected.

### 18.01 Masters overview (id 848)
- OST-18-001 Master tables live in the database: Employees, Job Statuses, Condition Types, Style Library and Sets, Default Layers (plus DPC payroll classes and labor cost codes with DPC licences).
- OST-18-002 Edits to Employees, Job Statuses, Condition Types affect all projects in the database. Edits to a Style or Style Set do not alter existing conditions. Default Layers affect only new projects.
- OST-18-003 Employee or Job Status in use cannot be deleted; employee owning a Style Set cannot be deleted. Master deletions are immediate and irreversible.
- OST-18-004 Lookup button in dialogs opens the master in Select mode (OK replaced by Select); masters can be built on the fly while using the program.

### 18.02 Employees (id 849)
- OST-18-005 Roles: estimators, laborers, project managers, foremen. Detail dialog: First Name, Last Name, Emp. No. required (Emp. No. unique); other fields optional; all text fields 50 chars max. Email useful for sending.
- OST-18-006 PM or Foreman in DPC mode locks Emp. No. and Access Level.

### 18.02.01 Importing employees (id 850)
- OST-18-007 CSV import with required headers EmpNo, FirstName, LastName; others optional; template file shipped in the OST documents folder. Import button in Employees master.
- UNKNOWN: full list of optional CSV headers (only shown in image) and duplicate-EmpNo handling.

### 18.03 Job statuses (id 851)
- OST-18-008 Status assigned on Cover Sheet or via right-click Change Job Status on a project; name max 50 chars; new bids take the first status in the list; Move Up/Down reorders; Print lists statuses with lock flags.
- OST-18-009 "Lock Bid" flag per status: projects in that status open read-only for everyone. Applies to base bid plus all alternates and change orders. Global to database.
- OST-18-010 Can add status on the fly by typing in the Cover Sheet field. Projects tab can group by status.

### 18.04 Condition types (id 852)
- OST-18-011 Type is a tag (max 50 chars) used to group Conditions list, Style Library, Summary and Estimate. Optional; blank shows as "Unassigned".

### 18.05 Style library overview (id 853)
- OST-18-012 Style = saved Condition template. Four fixed system styles: Linear, Area, Count, Attachment (not editable). Saved styles are not auto-added to any set. Library grouped by Condition Type.

### 18.05.01 Create/update/delete styles (id 854)
- OST-18-013 New via Master > Style Library and Sets; Style Properties dialog mirrors Condition Properties; name max 75 chars. Change (or double-click), Duplicate, Delete available. Style in a Set must be removed from the Set before deletion. Changing or deleting a style never touches conditions already made from it.

### 18.05.02 Style sets (id 855)
- OST-18-014 Set = named group of styles (name max 50 chars, has Owner). Create from selected styles via New Set, add more using Add then Lookup (multi-select with Ctrl/Shift/Ctrl-A). Sets list shows owner and style count. Change renames or edits members. Delete set has no effect on bids. Rights-dependent.

### 18.06 Default layers (id 856)
- OST-18-015 List of layers auto-added to each new bid (base, alternates, change orders). Show checkbox sets initial visibility. Reorder with Move Up/Down. Not retroactive to existing bids.
- OST-18-016 Distinct from the bid-level Layers dialog (per bid).
- OST-18-017 Permanent system layers: Image (plans), Annotation (hot links, text, dimension lines, image legend), Default (takeoff of conditions with no layer, "unassigned"), Comments (comment icons).

### 19.01 Customizing overview (id 857)
- OST-19-001 Program options (General, Fonts/Colors, Sounds, Folders, Analytics) are per Windows user, stored in local registry, apply to all databases. Database options (New Project tab) live in the database and affect all its users; apply only to bids created afterward.
- OST-19-002 Reset All Settings: restores program options and window settings, drops references to databases outside default folder, leaves New Project settings and analytics opt-in unchanged. Irreversible.

### 19.02 General tab (id 858)
- OST-19-003 Preferences (default in brackets): Enter key moves between dialog fields (on); show text on toolbar (on); roping method Inclusive vs Touching (Touching); default dialog for Condition change OST Properties vs QuickBid details (OST); right angle indicator (on); Connect linear takeoff default (on); hot link target window View/Annotation/Main (Annotation).
- OST-19-004 Display page index and sheet number beside sheet names (both on). Full-window crosshairs with colour and thickness (off). Restrict lateral movement of linear objects (off; per the text linear objects by default move only up and down). Allow adding page from Image tab via next-arrow on last page (on; new page has no image).
- OST-19-005 Prompt to refresh worksheet before closing bid when pricing via Excel (on). Disable high resolution images (off; on forces 2-bit rendering, off gives 8-bit). Auto dimension lines (flag text says check to disable; default off). Automatic continuous mode on click-drag (off). Intelligent Paste (on). Advanced mouse controls for wheel and right-button pan/zoom (on). Active Area filter in print preview (on; prints only takeoff in the page's active area).
- OST-19-006 Snap angle: 0 = free; 90 = only 0/90/180/270; intermediate values snap to multiples. Separate values for Shift unpressed/pressed. Defaults: mouse 15 and 0; digitizer 0 and 15.
- OST-19-007 Intelligent Curve Segment slider Fewer..More (default midpoint) sets how many segments a curve is split into.
- OST-19-008 Confirmations: all confirmation dialogs (on), quick start wizards (on), bid wizard (off).
- OST-19-009 Default Auto Zoom Level: percent beyond which the area-takeoff magnifier is hidden; 0 disables.
- UNKNOWN: exact semantics of the auto dimension lines checkbox given contradictory wording; definition of "Active Area".

### 19.03 New Project tab (id 859)
- OST-19-010 Next Bid Number (sequential, default 1, used numbers skipped). Base measurement inches or millimeters (sets database Measure Mode). Hours/Day 8. Week start Sunday. Price Using default Estimate Tab (choices depend on licensed products). Takeoff increment: smallest measurable unit, default 1 inch or 10 mm.
- OST-19-011 New page defaults: page size E (30 x 42 inch), scale style Architectural, scale 1/8 inch = 1 foot. Advice: verify scale per page.
- OST-19-012 Connect Linear default on for new databases: connects perpendicular linear objects within the Tolerance.
- OST-19-013 Image Legend defaults: show Qty 1 only (Qty 2 and 3 off), quantity label Q1/Q2/Q3 off, show condition number on, show condition type off, sort by Number (or Name, Condition Type; only when legend is one block). Each condition has up to three quantity results (Q1, Q2, Q3).
- UNKNOWN: how Tolerance is measured; what Takeoff increment rounds (per vertex or final quantity).

### 19.04 Fonts/Colors (id 860)
- OST-19-014 Default font and colour per annotation item (text, area label, image legend, etc.); only affects new annotations. Dimension line colour applies to label text only; line always black. AutoNaming highlight colour and transparency for sheet number/name regions.

### 19.05 Sounds (id 861)
- OST-19-015 Four events: accepted point, rejected point, deleted object, completed object; WAV only; disable for mouse via "Use for mouse also" cleared; digitizer disabled by clearing file entries. System beep on completion remains.

### 19.06 Folders (id 862)
- OST-19-016 Folder settings and defaults: Database (OST documents folder), Backup (Backups subfolder; must differ from Database folder), Planroom (downloaded plans), Image Cache (temp images for packages, Cache subfolder), Package (default output of .osp), Update Location (blank; admin control of update notices). Invalid paths fail lazily.

### 19.07 Analytics (id 1036)
- OST-19-017 Obsolete (before 3.98.18.03); opt-in usage data. Skipped as marketing/telemetry.

### 20.01 What is a database (id 863)
- OST-20-001 Database stores takeoff, employees, styles, sets, project info, links to plan images (not images). Two shipped: example and blank. Organization by user, office, or project is a choice.
- OST-20-002 Types: Microsoft Access (single user, local) and SQL Server (sharing or network). Options do not transfer between databases, except via sync.

### 20.02 Open and close (id 864)
- OST-20-003 Open Databases dialog: checkbox per database; opens multiple at once, one bid editable at a time. Buttons: Properties (backup, auto-compress, measure mode, login), Compact/Repair, Backup (disabled for SQL), Find, Remove (removes reference only; not for default-folder databases). Close = uncheck or right-click > Close. Login prompt with remember option when secured.

### 20.02.01 Finding Access database (id 865)
- OST-20-004 Find > Microsoft Access > Lookup to file. Default-folder databases always listed and cannot be removed. Never work in the Backup folder, never keep Access on network/removable drive, never open one Access file with two users.

### 20.02.02 Connecting to SQL (id 866)
- OST-20-005 Find > SQL Server: server name (case sensitive in practice; every user must type identically; named instance as server\instance), auth Windows or SQL login, then pick from all databases on the server (not filtered to OST; include "OST" in name). SQL entries show no date or size and cannot be backed up by OST.

### 20.03 Create Access database (id 867)
- OST-20-006 File > New > Database. Properties: file name (default folder or path; avoid special characters), Requires login (available only after creation and after adding employees), Measure mode Imperial or Metric (drives all UOM boxes; do not mix in one database or connect Imperial OST to Metric QuickBid), auto-backup frequency (default weekly) and count (default 2), auto-compress frequency (default monthly).
- OST-20-007 Auto-backup runs on app close; oldest backup overwritten when count reached.

### 20.04 Create SQL database (id 868)
- OST-20-008 Created from inside OST, not the SQL console. Fields: server, auth, database name, measure mode, login flag later. No auto-backup/compress options (admin does backups and Shrink). OST is not client-server; installed on each workstation.
- OST-20-009 Migration path: sync masters from old Access to new SQL, drag-drop projects between open databases, verify, archive the old Access files out of user reach. Disconnect interactive OST-QuickBid projects before copying and reconnect after.
- OST-20-010 Sync from only one source into a database to avoid duplicates.

### 20.05.01 Upgrading (id 869)
- OST-20-011 Four maintenance tools: upgrade, compact/repair, synchronize, backup (Access only). Upgrade adds tables/fields on first open in newer version; irreversible, older versions cannot then open it. SQL upgrade needs dbo and full backup first; coordinate all users.

### 20.05.02 Compact and repair (id 870)
- OST-20-012 Repair works on Access and SQL, Compact on Access only. Only the running user may have the app open. Weekly suggested; more often with heavy copy/paste or package import. Context menu shortcut on Projects tab. Auto-compress runs on close and only shrinks file size.

### 20.05.03 Synchronizing (id 871)
- OST-20-013 Tools > Synchronize Databases: pick Source and Destination. Master tables only (no projects, not New Project options). Inserts missing rows and updates existing rows in destination; source untouched. General and Folders program settings are copied. Default all masters; or choose tables, with dependencies auto-ticked (Styles require Condition Types and Layers).
- OST-20-014 Master CloudSync: from 14 Sept 2026 org admins can sync masters to a cloud database named "Cloud" plus org name; all users can sync from it; non-admin sync-to errors. Master (Company) menu shows a view-only window of the cloud masters. Edits flow: sync cloud to local, edit, sync back.
- UNKNOWN: matching key used to decide "already exists" when updating.

### 20.05.04 Backup and restore (id 872)
- OST-20-015 Backup copies the Access file to Backup folder with numeric suffix (name1.mdb, name2.mdb rotating). On demand via Open dialog or right-click. Recommended: after every use, 10 copies. Restore = copy latest backup into database folder, open, compact/repair, recheck settings; restored file is an independent database.

### 20.06 Securing databases (id 873)
- OST-20-016 Database login is separate from product licence login. Needs at least one Administrator. Employees and access levels are per database. Default has only the Administrator level.
- OST-20-017 Access Level: description, "Set as System Administrator" (full access to everything, may change database properties and employees), then per-table setting Full Access / Read Only / No Access for four tables.
- OST-20-018 Others' Bids: bid ownership is the Estimator on the Cover Sheet. Full = view/edit all; Read Only = view others', edit own; No Access = cannot open others' (still listed, can still send them as package).
- OST-20-019 Projects/Bids List: Full = add/modify/delete any; Read Only = no new base bids, no delete base bids/folders, no import, but can add/modify/delete alternates and change orders; No Access = sees nothing (admin role).
- OST-20-020 Master: Full = edit all; Read Only = view only unless Styles/Sets granted; No Access = menu greyed unless Styles/Sets granted. Styles/Sets: Full overrides Master read-only; Read Only = view, cannot save; No Access = cannot open the lists but can still insert styles into a bid.

### 20.06.01 Require login (id 874)
- OST-20-021 Set via Database Properties > Logins Required, requires an admin credential; database then closes and reopens at login screen. Login each launch unless remember is ticked. Separate from network/SQL logins.

### 20.07 Concurrent users (id 875)
- OST-20-022 Only SQL may be shared. Recommended login required plus access levels. One editor per project: first user to activate Takeoff, Summary or Estimate tab locks the project (base, alternates, change orders) until they leave it.

## Category summary

### Category 16 (13 articles read)
- Two export artifacts: .osp (package, optional images and comments, matches origin bid) and .ost (data only, always creates new bid, feeds QuickBid).
- Page range selection on package export and the deletion consequence on overwrite.
- Import prompt create-new vs overwrite, new internal ID on create-new, DPC requires overwrite.
- Tabs report via print preview honoring sort/filter/group; PDF, Excel exports; CSV of Summary without headers.
- Version tag compare blocks importing newer files; 128 character path limit; 10 MB email limit.
- Secured source database yields a new secured empty-employee database on import.
- Missing masters (layers, types) auto-created on import.

### Category 17 (13 articles read)
- Project Express (retired) replaced by cloud project sharing: upload OSP of all pages, org-wide visibility, download to chosen open database, delete from cloud.
- Express links expire in 14 days; subscription checked on every action.
- Comments: threaded, per page, per bid, 50 char name, 250 char text, colour coded, in packages only, not takeoff.
- Collaboration pattern with a separate comments copy of each bid.
- Special characters in comment fields break package round trip.
- Dummy count condition trick to flag pages with comments or to force pages into .ost exports.

### Category 18 (9 articles read)
- Five masters and their blast radius (global vs new-only vs none for existing items).
- Delete protection when referenced.
- Job status with global lock flag making bids read-only; default is first in list.
- Condition Type tag, "Unassigned" fallback; styles are detached templates; sets are groups; four fixed system styles.
- Default layers vs system layers (Image, Annotation, Default, Comments).
- Employee import by CSV with 3 required headers.
- Field limits: 50 chars most names, 75 for style names.

### Category 19 (7 articles read)
- Program options per Windows user (registry); New Project options per database.
- Snap angle matrix by Shift state and input device; roping Inclusive vs Touching.
- New bid defaults: bid number sequence, base unit inch or mm, 8 hr day, page size E, 1/8 inch scale, takeoff increment, three quantity slots, image legend config.
- Folder roles and defaults.
- Reset behavior.

### Category 20 (13 articles read)
- Access (single user, local) vs SQL (shared) database types; Access never shared.
- Measure mode (Imperial or Metric) per database, do not mix.
- Auto-backup (weekly, 2 copies default) and auto-compress (monthly) on app close.
- Master sync semantics: insert plus update, masters only, dependency auto-select, cloud masters.
- Four-table access level model with Full/Read Only/No Access and ownership by Estimator.
- One-editor-per-project lock in shared databases.
- Upgrade is one-way.
